# Initial access

Here are some examples to look for malicious activity for initial access. Elastic stack is used for hunting and the example queries are in KQL language but the principle remains the same if there is another system in use.

## Brute-Forcing via SSH

List all failed SSH auth events on the host:

```
host.name: <host> AND event.category: authentication AND system.auth.ssh.event: Failed
```

Suucessful attempts:
```
host.name: <host> AND event.category: authentication AND system.auth.ssh.event: Accepted AND source.ip: <IP> or <IPs>
```

## Remote Code Execution

All ingress network connections to the web server:

```
host.name: <host> AND network.protocol: http AND destination.port: 80
```

If numerous 404 requests are found more info with:

```
host.name: <host> AND network.protocol: http AND destination.port: 80 AND source.ip: <IP> AND http.response.status_code: 404
```

Useful fields to look at for example:
- query
- user_agent.original
- url.query

Valid endpoints, aka non 404 requests:

```
host.name: <host> AND network.protocol: http AND destination.port: 80 AND source.ip: <IP> AND http.response.status_code: (200 OR 301 OR 302)
```

## Phishing links and Attachments

Phishing links downloaded using a web browser. Example of file creations (Sysmon Event ID 11) generated by chrome.exe:
```
host.name: <host> AND process.name: chrome.exe AND winlog.event_id: 11
```

Useful fields to look at for example:
- winlog.computer_name
- winlog.event_data.User
- file.path

Phishing attachments opened using an Outlook client:

```
host.name: <host> AND process.name: OUTLOOK.EXE AND winlog.event_id: 11
```
