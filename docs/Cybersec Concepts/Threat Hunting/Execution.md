# Execution

Here are some examples to look for malicious activity for execution. Elastic stack is used for hunting and the example queries are in KQL language but the principle remains the same if there is another system in use.

## Usage of Command-Line Tools

Process creations (Sysmon Event ID 1) generated by powershell.exe and cmd.exe:

```
host.name: <host> AND winlog.event_id: 1 AND process.name: (cmd.exe OR powershell.exe)
```

Useful fields to look at for example:
- winlog.computer_name
- user.name
- process.parent.command_line
- process.command_line

Alternative way to hunt unusual PowerShell execution is through the events generated by PowerShell's Script Block Logging:

```
host.name: <host> AND winlog.event_id: 4104
```

Useful fields to look at for example:
- winlog.computer_name
- winlog.user.name
- powershell.file.script_block_text

Known strings used in cmd.exe or powershell.exe can also be leveraged to determine unusual traffic. Some examples:

- invoke / invoke-expression / iex
- -enc / -encoded
- -noprofile / -nop
- bypass
- -c / -command
- -executionpolicy / -ep
- WebRequest
- Download

## Built-in System Tools

Built-in tools typically used by threat actors (Certutil, Mshta, and Regsvr32). Process creation (Sysmon Event ID 1) as well as network connection (Sysmon Event ID 3) events:

```
host.name: <host> AND winlog.event_id: (1 OR 3) AND (process.name: (mshta.exe OR certutil.exe OR regsvr32.exe) OR process.parent.name: (mshta.exe OR certutil.exe OR regsvr32.exe))
```

Useful fields to look at for example:
- winlog.computer_name
- user.name
- process.parent.command_line
- process.name
- process.command_line
- destination.ip


## Scripting and Programming Tools

Unusual events generated by programming tools like Python, PHP and NodeJS.  Process creation (Sysmon Event ID 1) and network connection (Sysmon Event ID 3) events:

```
host.name: <host> AND winlog.event_id: (1 OR 3) AND (process.name: (*python* OR *php* OR *nodejs*) OR process.parent.name: (*python* OR *php* OR *nodejs*))
```

Useful fields to look at for example:
- winlog.computer_name
- user.name
- process.parent.command_line
- process.name
- process.command_line
- destination.ip
- destination.port

All processes spawned by a process instance by using it as our process.parent.pid:

```
host.name: <host> AND winlog.event_id: (1 OR 3) AND process.parent.pid: <pid>
```
